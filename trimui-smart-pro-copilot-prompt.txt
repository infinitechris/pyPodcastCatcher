Build a portable podcast player app for the Trimui Smart Pro that works with the existing Podcast Catcher desktop application.

The desktop app organizes downloaded media like this:

downloads/
  Podcast Name/
    episode-file.mp3

The MP3 files may contain:

- ID3v2.3 metadata
- TIT2 episode title
- TALB podcast name
- APIC embedded podcast artwork
- TPE1 artist information
- Playback-related metadata where available

The desktop app also exports a synchronization manifest:

downloads/podcast-status.json
downloads/podcast-status.sha1

The JSON has this general structure:

{
  "version": 1,
  "episodes": {
    "<feed_url>|<episode_identity>": {
      "feed_url": "https://example.com/feed.xml",
      "episode_key": "https://example.com/episode.mp3",
      "played": false,
      "archived": false,
      "played_updated_at": null,
      "archived_updated_at": null,
      "playback_position_seconds": 0,
      "duration_seconds": null,
      "playback_updated_at": null
    }
  }
}

Episode identity is resolved in this order:

1. Audio/enclosure URL
2. Episode link
3. Episode title as a last resort

Build the device app around this existing file and JSON architecture.

CORE DEVICE BEHAVIOR

1. Scan the device storage for podcast directories and MP3 files.
2. Treat each immediate subdirectory under the podcast library directory as a podcast.
3. Read podcast and episode metadata from ID3 tags.
4. Read embedded APIC artwork from the MP3 when available.
5. Load podcast-status.json if present.
6. Validate it using podcast-status.sha1.
7. Display podcasts, episodes, played state, archived state, artwork, and playback progress.
8. Allow the user to browse podcasts using the Trimui controls.
9. Allow the user to play, pause, resume, stop, and seek within episodes.
10. Resume playback from playback_position_seconds.
11. Save playback position periodically and when playback stops or the app exits.
12. Mark an episode as played only when playback reaches the completion threshold, such as 95 percent or the player’s natural end event.
13. Do not mark a partially played episode as fully played.
14. Provide manual Played and Archived toggles.
15. Preserve the distinction between partial playback and completed playback.
16. Allow filtering or sorting by:
    - All episodes
    - Unplayed episodes
    - Played episodes
    - Unarchived episodes
    - Archived episodes
17. Never delete status entries merely because a file is absent from the device.

SYNCHRONIZATION RULES

The device app must write changes back to:

podcast-status.json
podcast-status.sha1

Use atomic writes:

1. Write to a temporary JSON file.
2. Flush and close it.
3. Replace the original JSON file.
4. Recalculate SHA1 from the exact final JSON bytes.
5. Write the SHA1 file only after the JSON replacement succeeds.

Use UTF-8 JSON with stable formatting and sorted keys.

Preserve:

- Unknown top-level fields
- Unknown episode entries
- Future fields added by the desktop app
- Episode entries for files that are no longer currently present

Do not overwrite the entire manifest with only the files currently visible on the device.

CONFLICT HANDLING

The desktop and device may both change state independently.

Resolve conflicts per field:

- played uses played_updated_at
- archived uses archived_updated_at
- playback position uses playback_updated_at

Use the newest valid UTC timestamp for each field.

If one side has no timestamp:

- Preserve the value that already has a timestamp.
- If neither side has a timestamp, preserve the existing value.
- Do not silently overwrite a value when the conflict cannot be resolved.
- Log or display a concise synchronization warning.

Do not treat SHA1 as a security mechanism. It is only an integrity check for accidental or incomplete file changes.

If the JSON is malformed or the SHA1 check fails:

1. Do not destroy the original files.
2. Preserve a backup copy if possible.
3. Attempt to parse and compare the JSON content.
4. Report the problem to the user.
5. Continue in read-only mode if the media library can still be scanned.
6. Never silently reset all episode states.

DESKTOP COMPATIBILITY

The desktop app currently supports:

- Per-podcast download counts
- Per-podcast download filters for played and archived episodes
- Played and archived states
- Partial playback position
- Oldest-first catch-up mode
- Priority downloads
- RSS-derived titles
- RSS-derived album names
- Embedded podcast artwork
- Autonomous all-feed watching
- JSON and SHA1 status export
- Per-field UTC update timestamps for synchronization

Do not assume the device can access the desktop SQLite database.

Do not require network access on the Trimui.

The device app should work when the user copies the downloads directory and status files to the device storage.

PROPOSED DEVICE WORKFLOW

1. Desktop Podcast Catcher downloads episodes into podcast folders.
2. Desktop Podcast Catcher exports podcast-status.json and podcast-status.sha1.
3. User copies the podcast folders and status files to the Trimui.
4. Device app scans the files and loads the status manifest.
5. Device app updates played, archived, and playback progress state while listening.
6. User copies the status files back to the desktop.
7. Future desktop synchronization tooling can compare and merge the returned status manifest.
